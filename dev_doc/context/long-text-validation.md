# 长文标注验证

日期：2026-09-28。软件版本：0.2.0。

用户要求标出长文中的三档片段并结构化保存，并明确选择敏感筛查：任一模型高分即突出。

## 已验证结果

| 检查 | 结果 |
|---|---|
| 100,000 字符长文 | 270 个片段，四模型共 1,080 次片段判断，全部成功 |
| 本机首次模型加载 + 标注 | 9.275 秒，RTX 4060 Ti；不含 Python/模块导入和报告写入时间 |
| PyTorch 峰值已分配显存 | 1,676.4 MiB；不包含完整驱动和其他进程占用 |
| 全文覆盖 | 无遗漏、无重复；各片段原文可完整拼回 100,000 字符 |
| 离线 | 阻断推理进程的 socket 连接后仍完成全部计算 |
| 跨片段批处理 vs 单片调用 | 最大分数绝对差 2.99×10⁻⁷ |
| 契约测试 | 25 项通过，覆盖分档边界、长文、Unicode/CRLF、非法参数、报告一致性、禁止覆盖、HTML 文本转义 |
| 原始检测接口回归 | 8 样本 × 4 模型共 32 次试跑通过，作者公式和 CPU/CUDA 对照通过 |
| 真实 HTTP / CLI | 从 dissertation 工作目录调用成功，标注决策与原文 hash 一致 |
| 十万字符实际 HTTP 请求 | 已加载模型的服务约 8.161 秒完成；返回 270 片段，源文本完整还原 |
| 服务更新 | 已重启为 0.2.0，`POST /v1/annotate` 可用 |

测试长文由既有 HC3 官方六条回答以 CRLF 空行连接，重复后取前 100,000 Unicode 字符。它用于工程验证，不能估计真实十万字论文的准确率或普遍耗时。未从 dissertation 读取正文做检测。

另外验证了可配置的大于 512 token 的片段：内部多窗口覆盖与全局原文位置正确；只有不可编码控制字符的片段保留在报告中，标记 `no_scorable_tokens`，不伪造模型分数。

## 分档与限制

默认高分线 0.90、中间线 0.70 是本轮实现的可配置筛查规则，未根据任何样本调整或校准。报告保留 `calibrated=false`、原始分数、触发模型、不同模型的分歧、模型 revision 和规则版本。

当前标注精度是片段，默认每片最多 400 字符。单个片段中人类/AI 文本可能混合，不能从片段分数得出精确的生成起止位置。“其他”表示没有达到当前规则，不认证为人类写作。

HTML 的数据嵌入、无外部资源依赖、源文本转义和 JavaScript 语法检查通过。**内置浏览器的 URL 安全策略禁止 `file://`，因此未完成浏览器视觉与交互实测。** 没有通过另起服务器或其他浏览器绕过该限制。用户可直接在自己的浏览器打开报告文件复核。

测试库仍有一条 Starlette/httpx 弃用提示，不影响通过结果。
