# 文档分层与更新触发

| 层 | 保存什么 | 何时更新 |
|---|---|---|
| `user_doc/` | 调用方需要执行的步骤、参数和结果解释 | 公开接口或使用流程变化 |
| `architecture/` | 当前组件职责、数据流、不变量 | 依赖关系、数据保存或运行边界变化 |
| `blueprints/` | 模块如何实现、入口文件、扩展点 | 模块职责、算法或代码布局变化 |
| `terminology.md` | 需要统一解释的项目术语 | 新术语出现或含义变化 |
| `development_environment.md` | 机器和依赖的已验证快照 | 重装/升级并通过验证后 |
| `context/` | 带来源和日期的决策依据、实验上下文 | 获得跨会话有用的证据 |
| `toDo/` | 需用户主动触发的未来工作 | 用户授权、完成或取消时 |
| `toDo/auto/` | 有明确事件、边界的维护触发条件 | 条件变化或任务完成时 |
| `change_records/` | 已完成的实质变更、验证与影响 | 完成可交付改动后 |
| `change_records/minor/` | 小修复和局部整理 | 小变更完成后 |
| `obsolete/` | 已失效但有追溯价值的材料 | 明确被替代或取消时 |
| `history.md` | 主要阶段的简短索引 | 建立一个新的可用阶段后 |

每个事实尽量保留一个权威位置，其余用链接引用。context 不充当待办或发布记录；change_records 不记录未实现计划。变更记录用 `YYYYMMDD_HHMMSS_主题.md` 命名，以实际完成时间为准。历史记录保留原语境，新结论写新记录或明确的补注。
