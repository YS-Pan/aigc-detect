# 维护流程

## 开始

1. 读取根 `AGENTS.md`、开发入口、本文件。
2. 区分调用已有服务、维护实现、更新模型、修改文档；进入相应用户指南或模块说明。
3. 检查与任务相关的待办、来源证据和现有文件，避免覆盖他人的运行报告。

## 实施

- 使用本工作区解释器和源码。`models/` 保存大文件，manifest 保存可追溯元数据。
- 只修改授权范围。调用方目录不因本服务维护而自动获得修改授权。
- 网络下载遵循用户的直连优先要求。推理始终本地运行。
- 改接口时同步输入约束、字段解释和跨工作区示例。改模型时核对标签顺序、tokenizer、最大长度与许可证来源。
- 改长文融合时核对 profile 锁定的完整十模型 revision、400/120 分片和拟合来源；门限只从 profile 读取，文档不抄写综合门限数值。人写控制样本的额外权重和零标记约束只用于拟合，运行时仍只用模型分数。
- 报告参考集拟合结果、留出重拟合诊断和真正独立测试时，明确区分三者。已参与超参数或门限选择的资料不称为独立测试，也不据此宣称准确率或泛化已验证。

## 验证

- API/推理变化：运行相关契约测试和有意义的真实模型试跑。
- 权重/依赖变化：检查哈希、`pip check`、离线加载和至少一条官方样本。
- 仅文案变化：检查链接、命令和表述，无需重复 GPU 推理。
- 测试报告记录实际运行结果；不把待执行检查写成通过。

## 收尾

按 [文档职责](documents.md) 同步现状和用户行为。完成的变更进入 change_records，未完成事项进入 toDo，实验细节进入 context 或 reports。更新相关索引。已完成的待办从活动列表移除并链接到完成记录；只有失效历史需要保留时才移入 obsolete。

本项目不自动增加未来范围、定时任务或阈值。Git 已在本地 `main` 分支初始化且无 remote。版本管理源码、文档、`models/manifest.json` 和不含具体文本的轻量证据；虚拟环境、权重、原始私人材料、完整报告、CNKI PDF、checkpoint 和缓存排除。绝不把具体正文或完整报告纳入 Git。
